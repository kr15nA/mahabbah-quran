# ATTENDANCE-SCHEMA-HOTFIX-001

## 1. Root Cause
The `upsertAttendance` query implementation in `lib/db/queries/attendance.ts` utilizes an `ON CONFLICT (student_id, attendance_date)` clause. Postgres requires a unique constraint or index on the conflict target for this upsert behavior to function correctly. 

## 2. Previous Schema Drift
Historically, `drizzle/schema.ts` did not define this constraint, meaning formal migrations generated by Drizzle omitted it. Instead, the `drizzle/seed.ts` script manually injected a `CREATE UNIQUE INDEX IF NOT EXISTS attendance_unique_per_day` statement. This led to schema drift: the database implicitly supported the constraint via the manually injected index, while newly provisioned environments skipping the seed would fail at runtime. `ACADEMIC-CONTEXT-001` identified this drift and temporarily formalized it in `drizzle/schema.ts` but did not execute the corresponding migration to avoid scope creep.

## 3. Duplicate-Data Safety Check
Prior to applying the migration, a scan was executed against the database grouping by `student_id` and `attendance_date`. The `HAVING COUNT(*) > 1` query returned exactly `0` duplicate rows, verifying the safety of enforcing the unique constraint immediately on existing data.

## 4. Formal Migration Created
Drizzle migration `0005_big_puff_adder.sql` was generated. To guarantee idempotency across both fresh and existing environments (which may already possess the legacy index from `seed.ts`), the migration script was modified to perform:
```sql
DROP INDEX IF EXISTS "attendance_unique_per_day";
ALTER TABLE "attendance" ADD CONSTRAINT "attendance_unique_per_day" UNIQUE("student_id","attendance_date");
```

## 5. Actual DB State
- **Before:** Existing environments utilized an underlying unique *index* (`attendance_unique_per_day`) created by the seed, not formally tracked by Drizzle.
- **After:** The formal unique *constraint* exists directly as `attendance_unique_per_day` mapped via Drizzle schema definition, backed by standard Drizzle migration execution.

## 6. Seed Cleanup
The explicit `CREATE UNIQUE INDEX IF NOT EXISTS attendance_unique_per_day` statement in `drizzle/seed.ts` has been removed. Schema ownership is fully restored to Drizzle migrations.

## 7. Testing & Validation
- Created a robust regression test `scripts/test-attendance-regression.ts` validating correct upsert behaviors across `same-student/same-date`, `same-student/different-date`, and `different-student/same-date` scenarios, along with rigorous RBAC access checks.
- All tests (`scripts/test-academic-context.ts` and `scripts/test-attendance-regression.ts`) completed successfully.
- Typecheck (`npx tsc --noEmit`) and production build (`npm run build`) succeeded without warnings or errors.

## 8. Remaining Risks
The initial migrations were bypassed through `drizzle-kit push`, requiring this migration to be explicitly applied manually against environments depending on their initialization mechanisms (as standard `drizzle-kit migrate` mechanisms lacked preceding sync history).
